# AlphaZero ↔ GoCube V2 verification report

> Authority: historical record of the evidence and checks completed for AlphaZero ↔ GoCube V2 verification. It is not a source of current product requirements, roadmap scope, or architecture and does not override `docs/GAME_CUBE_GO.md`, `docs/ROADMAP.md`, or `docs/ARCHITECTURE.md`.

## Scope

V2 verifies the logical AlphaZero/GoCube product boundary from the F0-integrated
AlphaZero tree.  Expected MAIN values are exported from the independently
verified V1 fixture registry and are imported as untrusted JSON into a strict
test-only GoCube validator.  GoCube's renderer is not part of the rule oracle.

The product lifecycle remains:

```text
MAIN → second Pass → endgame review → manual/automatic classification → score
```

AlphaZero's post-boundary training cleanup is recorded as `V2-DIFF-001` and is
not implemented in GoCube.

## Acceptance results

The authoritative row-level index is
[`ALPHAZERO_V2_COMPATIBILITY_MATRIX.md`](./ALPHAZERO_V2_COMPATIBILITY_MATRIX.md).
The automated V2 product suite covers:

- strict schema/provenance/komi/action validation;
- full Cube4 PointId bijection and adjacency comparison;
- exact per-step legality, captures, occupancy and player-to-move replay;
- Cube seam/vertex and Torus wrap fixtures;
- occupied, suicide, true-ko and unknown-point rejection without mutation;
- accepted-second-Pass atomicity for classifier exceptions and invalid proposals;
- manual review completion and exact Japanese `FinalScore` for the verified
  empty setup fixture;
- repository snapshot round-trip and fresh-score validation;
- rejection of partial/non-stone groups and tampered `FinalScore` metadata.

The representative browser smoke exercises the same product boundary shape
through Cube 2D UI: empty verified setup, two Passes, manual review entry and
Japanese result `White wins by 0.5`.  Core integration tests remain the primary
evidence; browser clicks are not used for differential rule assertions.
